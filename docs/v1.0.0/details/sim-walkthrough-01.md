# Snowel 架构推演记录 #01 —— 从零模拟一次小说创作

> 日期：2026-08-23
> 形式：角色扮演推演。Snowel 工具本体（CLI + MCP + 知识图谱）由 AI 扮演，作者全程真实决策。
> 目的：从零走一遍 Layer 1→5 的完整创作流程，暴露架构设计问题，收集真实需求。
> 结果：发现并记录问题 **#0 ~ #31**，得出「分形雪花 + 知识图谱 + 回写环 + 混合检索 + MCP」的总架构。

---

## 一、背景：为什么做这次推演

原有架构（FastAPI Web 后端，已删除）只实现了雪花法 Layer 1/2 的生成，无法支撑**超长篇小说**创作。核心痛点（作者原话归纳）：

1. 人物设定的历史可追溯、动态更新，以及不同题材的人物模板差异（玄幻/都市/恐怖/科幻各不相同）
2. 场景、大纲等结构资产需要不断演进
3. CLI + MCP 架构是否合理
4. 需要知识图谱或类似的数据存储结构，并规范本体（ontology）
5. 原雪花法没有讨论创作过程中各要素的**关联与检索**

核心结论：**雪花法是写作流程，不是数据模型。** 它解决了"从粗到细的生成路径"，没有解决"长篇创作中的知识管理"。两者必须分开设计、再咬合。

---

## 二、推演过程完整记录

### 第 0 步：创建项目

```bash
$ snowel init "我的第一一本书"
```

内部动作：
- MCP `create_project` → 图写入 `Project` 根节点 + 5 个 Layer 占位节点
- 创建 `snowel.db`（SQLite + 边表起步）与 `workspace/` 目录

**决策**：init 时不决定题材，题材扩展包后挂（`snowel genre add <pack>`），只影响可挂载属性组，不动已有数据。

### 第 1 步：Layer 1 —— 灵感雪核

**作者输入**：题材「奇幻架空 + 无限流」；灵感口述约 200 字——主角每天强制获得额外时间进入异空间，全人类参与者探索挑战、排名、获取超能力与奇物带回现实；排名不达标则额外时间越来越长，直到永远回不来。

**Snowel 动作**：
- `capture_brainstorm`：原始灵感**原文存档**（作者原话永远保留，是 Layer 1 节点附属全文）
- `ai_generate(premise)` 产出 A/B 两个一句话梗概提案
- 同时抽取 4 个设定概念节点（draft 暂存）：异空间 / 额外时间规则 / 排名制度 / 奖励体系

**作者决策**：A+B 合并。

> 最终梗概：一个普通人被迫每天坠入不断延长的异空间挑战赛，他发现排名制度的真相是一场跨越现实与异界的筛选——他必须赢下这场自己从未同意参加的游戏，否则终有一天将永远回不到现实。

落库：`Premise v1 (confirmed)` `-[:DERIVED_FROM]->` Brainstorm 原文 `-[:INTRODUCES]->` Concept ×4。

**讨论：设定完善放在哪一层？→ 都不是，是纵贯轨道。**

```
Layer 1  播种：从灵感抽取概念节点，只求捕获不求完整
Layer 2  施压：写摘要时冲突逼问缺什么设定
Layer 3  交汇：角色档案反推设定
Layer 4+ 校验：场景卡做一致性检查
正文期   回写：每章正文产出新设定细节，设定库持续生长
```

设定库（Concept 子图）是与五层并行的纵向轨道，每层做「写入 + 检查缺口」两个动作。缺口可 **TODO 化**——不强行填完，避免卡死灵感。需要 `setting_gap_report` 工具。

### 第 2 步：Layer 2 前半 —— 一段式摘要

`ai_generate(one_paragraph_summary)` 提案五句式摘要（设定 → 三大灾难 → 结局），并附带 `setting_gap_report` 发现的 3 个缺口作为**待作者决策项**（AI 不擅自补）：

> 每天凌晨三点，林晚被拖入异空间，数十万"被选中者"靠挑战争夺排名，超凡之力可带回现实。**灾难一**：排名垫底导致额外时间失控延长，重返现实的窗口正在关闭；**灾难二**：垫底者的"消失"实为向高位存在输送寿命，好友即将垫底；**灾难三**：掀翻制度必须登顶，而登顶条件是成为制度的一部分。最终林晚以"额外时间"为赌注发动规则漏洞摧毁筛选机制。

**作者决策**：摘要不改；缺口①填「曾有濒死体验」（注意：填缺口自动生成了新 Concept 节点）；②③标 TODO。伏笔在 Layer 2 介入 —— **同意**。

### 第 3 步：机制具体化 —— 「规则漏洞」的诞生

作者反问"规则漏洞是什么" → 引出流程：**正文要用的机制必须在登记时具体化**，不能留哑弹。

`elaborate_mechanism` 检索已确认概念 + 一致性约束检查，给出三方案：

1. **双生时间**：异空间时间有现实镜像，镜像不受排名约束
2. **垫底者契约**：规则写"末位永久滞留"，但没考虑"已经死过一次"的濒死体验者——末位惩罚天然失效，但每次利用都要真实濒死一次（代价型）
3. **排名套利**：排名禁止交易但允许转让，组织垫底者联盟操纵排名曲线（社会派）

**作者决策（关键，触发级联修改）**：
- 方案 2 采纳，但**重新定位**：林晚是穿越者（平行宇宙，原身已死，他在原身上复活），异空间因此误判其为濒死体验者——这是**中期卡 bug 的优势设定**，不承担结局功能
- 结局的规则漏洞改用**方案 3（排名套利）**

Snowel 触发**级联检查警告**：摘要 v1 的结局写的是方案 2 用法，与新决策冲突 → 生成修订提案（diff 式）：

> v2 结局：中期林晚凭"已死过一次"卡出盲区步步登顶；最终与垫底者联盟操纵排名曲线发起套利总攻，从制度内部撑爆筛选机制。

落库要点：
- `Character 林晚 (draft)` —— 主角提前于 Layer 3 诞生
- `Mechanism 垫底者契约 {narrative_role:"mid-story_advantage"}` `-[:EXPLOITS]-> 排名制度` `-[:REQUIRES]-> 被选中标准`
- `Mechanism 排名套利`；伏笔「最终规则漏洞」PAYOFF_VIA → 排名套利；新增伏笔「穿越者盲区」（payoff window = 中期登顶线）

### 第 4 步：Layer 2 后半 —— 一页纸大纲（18 拍节拍表）

`ai_generate(beat_sheet)` 上下文注入：摘要 v2 + Concept + Mechanism + 未回收伏笔 + 无限流题材节拍偏好（3 拍内进入第一空间）。

三幕 18 拍（精选）：

```
第一幕：坠入
 1. 凌晨 2:59 林晚猝死般惊醒，前世记忆归位
 2. 3:00 强制坠入「首夜」白雾广场，数十万人影，头顶悬浮排名
 3. 新手挑战「沉默房间」：濒死体质意外免疫判定，首次卡盲区 ⚠伏笔[穿越者盲区]
 4. 首次结算：排名 48 万+，奖励「哑铃铛」（无用物品?）
 5. 日常崩塌开始：同事中也有被选中者
 6. 【灾难一】连垫底三月，额外时间延至 5h/天，现实开始"褪色"

第二幕：登顶线
 7. 「回声长廊」结识联盟核心，垫底者抱团
 8. 垫底者互赠排名碎片微量续命，联盟雏形 🌱(排名套利·种子期)
 9. 「殡仪馆」副本：扮演死者，全场只有他游刃有余——盲区第二次兑现
10. 排名入前 1 万，获能力「时滞」；现实线：濒死体验者互助会
11. 【灾难二】垫底者消失=寿命输送；最好的朋友即将垫底
12. 挽救失败，朋友（陈叠）消失
13. 低谷抉择：独登顶 vs 联合垫底者
14. 联盟正式化，排名套利升级为战略武器

第三幕：撑爆它
15. 【灾难三】登顶条件曝光：盟主须献祭全部额外时间
16. 总攻：联盟操纵排名曲线，系统被迫超发寿命
17. 规则反噬：林晚主动垫底，用盲区接住制度全部恶意
18. 筛选机制内爆；林晚失去额外时间，保留那枚哑铃铛 🔔(回收第4拍)
```

落库结构：每拍 `DERIVED_FROM` 摘要对应句；拍 3/9 `PLANTS` 伏笔；拍 8/14 `DEVELOPS` 排名套利；拍 4/18 物品伏笔闭环（哑铃铛）；拍 6/11/15 `IS_DISASTER`。

**作者决策**：全部通过。

### 第 5 步：Layer 3 —— 角色血肉

**人物模板 = 属性组拼装**（本步验证了题材适配方案）：

```
[核心]    动机 / 恐惧 / 谎言信念 / 弧光        ← 所有题材通用
[无限流]  空间资历 / 排名轨迹 / 能力清单 / 盲区特权
[社会]    现实身份 / 现实线牵绊               ← 本书现实线重
```

**林晚档案（draft → profiled）**：

| 层 | 内容 |
|---|---|
| 动机 | 表层：活下去夺回正常生活；深层：在两个世界都"死过一次"的人，想要一个不会随时被没收的归属 |
| 谎言信念 | "我只是侥幸活下来的局外人，任何制度都与我无关"——全书弧光就是砸碎这句 |
| 恐惧 | 不是死亡，是"消失得无声无息"——垫底者命运的镜像 |
| 弧光 | 卡盲区独活 → 目睹朋友消失 → 发现"局外人"是逃避 → 选择成为制度的靶心 |
| 无限流组 | 资历首夜起；排名轨迹 48万→1万→主动垫底（全书唯一主动下坠的轨迹线）；能力「时滞」；盲区特权 |
| 社会组 | 外包程序员，社保断缴边缘；牵绊：互助会、陈叠（拍12亡） |

配角：**陈叠**（挚友，拍 12 死亡，需 `death_beat` 锁定）；**联盟核心三人**（各带一种垫底理由，让制度之恶有面孔）；**反派 = 排名制度的人格化**（制度型反派，Concept+Character 混合建模）。

落库要点：`Relationship` 升格为**节点**（带 from/to 拍、强度曲线）；角色 `-[:ARC_SPANS]->` 关键拍；反派 `-[:EMBODY]->` 排名制度。

**作者决策**：全部通过。

### 第 6 步：Layer 4 —— 场景脉络（节拍 → 场景卡）

`expand_beats`：1 拍 ≈ 1–4 张场景卡，每卡必含 POV/目的/冲突/转折/钩子。全书约 45–60 卡。伏笔定位自动从 beat 层传播到 scene 层（原定位保留为历史层）。

拆卡示例：拍 1 → 场景 1.1「2:59」；拍 4 → 4.1「首结算」+ 4.2「哑铃铛」；拍 6 → 6.1「现实褪色」+ 6.2「五小时」。

**重大发现：双时间轴**。无限流题材中每个故事日里异空间 N 小时 / 现现实固定时刻，时间本体必须是**多轨道 Timeline**（现实轨/异空间轨/回忆轨），场景挂轨+挂时长，才能回答"第 40 个故事日时林晚累计在异空间多久"。单轴模型在此题材直接报废。

**作者决策**：全部通过，进入 Layer 5。

### 第 7 步：Layer 5 —— 正文绽放（场景 1.1「2:59」）

**写前 `compose_context`（上下文自动组装）**：
- 图谱精确拉取：场景卡 + 林晚档案（按需裁剪属性组）+ 在场角色 + 未回收伏笔 ∩ 相关项 + 已确认世界观（TODO 项排除）
- 向量模糊召回：正文库为空时为空
- 组装结果约 800 token —— 检索精度决定 Layer 5 生死

**生成正文（节选）**：

> 凌晨两点五十九分，林晚在工位上醒来。
> 颈椎发出久坐者熟悉的、细小的抗议。显示器的休眠光标一闪一闪，像某种耐心的倒计时。他记得自己刚才在改一个永远改不完的报错——不对，他记得的东西比这多得多。多得不正常。
> 一整个世界。
> 六十七年的婚姻、另一个名字、另一种口音的告别。那些记忆此刻正安安静静地躺在他的脑子里，像退潮后留在沙滩上的东西，湿的、咸的、不属于这里的。
> 手机在桌上震动了一下。锁屏时间跳向三点整。
> 世界熄灭了。

**写后 `extract_and_writeback`（回写环）**——LLM 抽取事实，逐条与图谱比对，三种命运：已知且一致→忽略；全新→分级提案入库；冲突→警告。本场景抽取：「67 年前世婚姻」为**即兴新细节**；状态事件：位置变更、知识获得（前世记忆归位）入状态账本。

### 第 8 步（后续讨论）：分形雪花

作者提出：正文按篇章/场景写作时，是否应对每个小单元嵌套执行雪花五步法？

**结论：分形雪花成立，但不是简单递归：**

```
🏔 大雪花（全书 L1-5）—— 本次推演走完的流程
 ❄️ 中雪花（卷/篇章）—— 输入：本卷节拍区间 + 上卷末世界状态；
      流程：卷级主题 → 卷级三幕 → 本卷场景卡滚动展开。
      价值：300 章的书不可能 Layer 4 一次排完，每卷开工前才展开（滚动式规划）；
      中雪花边界 = 冻结线（写第 3 卷不得改第 1 卷正典，除非走显式 retcon）
  ✱ 小雪花（单章）—— 压缩为三步，受限展开而非从零生成：
      L1' 本章意图（结束时读者知道/感到什么，一句话）
      L2' 微节拍（本章 3-6 个微转折）
      L5' 成文 → 与场景卡对账 → 回写环
      砍掉 L3（角色档案现成，只需拉取）；微节拍作 MicroBeat 节点挂 Scene 下
```

层级间允许修订（卷改书、章改卷），但统一走「提案 → 级联影响分析 → 确认」的同一套 revision 流程——实现一次，三层受益。

## 三、问题清单（#0 ~ #31）

### 本体设计

- **#0** init 不定题材；题材扩展包后挂，只影响可挂载属性组
- **#1** 数值型机制需要护栏字段（growth_curve 等），声明指数增长时工具应在 Layer 1 警告数值崩坏
- **#2** 无限流题材命脉是规则体系（Mechanism 属性组：规则原文/生效范围/漏洞/数值曲线）；恐怖题材需要 Taboo 组——题材扩展包按需提供属性组
- **#3** 灵感原话与提炼物分开存，原文是 Layer 1 附属全文
- **#16** 人物模板 = 属性组拼装（核心组永远在场：动机/谎言/恐惧/弧光），而非整模板替换
- **#17** Relationship 必须是节点（带起止、强度曲线），不能是图数据库静态边
- **#18** 制度型反派需要 Concept+Character 多重类型支持
- **#20** 时间本体必须多轨道 Timeline（现实轨/异空间轨/回忆轨），Layer 4 前定稿
- **#28** 小雪花是"受限展开"不是从零生成；嵌套的是方法论精神（L1'→L2'→L5'），不是全部五层
- **#30** 小雪花产出 MicroBeat 节点入图谱，作为滚动上下文（比正文全文便宜）与伏笔微调粒度

### 演进机制

- **#5** 梗概合并等确认操作要记录血缘（lineage），可回答"这个设定怎么来的"
- **#9** 级联检查必须双向：写入新数据时向前查矛盾，修改旧数据时向后查依赖（含 `IS_A`/`REQUIRES`/`EXPLOITS` 边反查）
- **#10** 节点创建时机 ≠ 完备时机；character 需 completeness 状态（draft→profiled→active）
- **#11** Mechanism 需要 narrative_role（advantage/finale/worldbuilding/red-herring）——同一机制的叙事位置影响伏笔与大纲
- **#29** 中雪花边界 = 冻结线；改动已正典化设定须走显式 retcon 流程
- **#31** 层级间修订统一走「提案 → 级联影响分析 → 确认」revision 流程，分形复用

### 交互设计

- **#4** 提案确认应是 diff 式（接受/改写/合并），不是简单二选一
- **#7** 每次 fill_gap 落库后回显"图谱影响了什么"，让作者对知识库膨胀保持感知
- **#14** AI 自埋伏笔必须标 origin:"ai"，作者有否决权
- **#21** Layer 4 交互单位是"拍"不是"全书"：预览拆分 → 逐卡确认/合并
- **#22** POV 分布可视化（纯统计），Layer 4 调 POV 比写完再调便宜百倍

### 伏笔管理

- **#6** 伏笔注册最早发生在 Layer 2（如"规则漏洞"这类 L2 随口一提、L5 才兑现的东西）；每层生成自动注入未回收伏笔清单
- **#13** 伏笔 planted_at 支持多层定位（beat → scene → chapter 区间），层间换算自动传播
- 死亡角色 death_beat 锁定（陈叠），正文期检索自动附带"已死亡@拍N"

### 检索架构

- **#23** Layer 5 上下文预算：300 章后检索必须精确到"当时在场角色 + 未回收伏笔"；图谱精确拉取为主、向量兜底召回相似场景
- **#27** 加 retrieval_audit 模式：记录每次上下文组装了什么，作者事后标记"AI 忘了 X"，用真实失误数据校准检索策略

### 回写环

- **#24** 即兴细节一旦入正文自动升格正典；回写分级——低敏感自动入典，高敏感（数字/人名/规则）需作者确认；全文索引支持反查
- **#25** 正典分层：图谱=结构化正典，正文=叙事正典；抽取提示词须带"忽略修辞"判据，防图谱污染
- **#26** 回写抽取成本 = 每章多一次 LLM 调用；可低重要章节批量抽取或用小模型

## 七、技术选型与架构决议（2026-08-23 复盘讨论定稿）

> 依据：本文档问题 #0–#31 + 复盘讨论。状态：已定稿（可后续修订）。

### 7.1 总架构：一个引擎核心 + 三个外壳

```
                    ┌─────────────┐
                    │  引擎核心    │  snowel-core（纯 Python，无 IO 框架依赖）
                    │  雪花流程    │  分形雪花 L1-5 / 卷级冻结线 / 章级小雪花
                    │  图谱+事件   │  本体 / 级联检查 / revision / 回写环 / 混合检索
                    └──┬───┬───┬──┘
                       │   │   │      三个外壳都是薄壳：参数校验 + 调用核心 + 回显
        ┌──────────────┘   │   └──────────────┐
   MCP Server (stdio)   CLI (typer)    FastAPI Backend ←→ React Web UI
   供任意 AI 客户端     本地管理/导出    最终面向作者的主创作界面（全流程）
```

关键原则：

1. **snowel-core 是唯一真相源逻辑所在**：雪花流程、级联检查、提案-确认、回写、检索组装全部在这里，可单测、三端零重复。
2. **LLM 调用集中在三个口**：每层 `ai_generate`（提案）、`extract_and_writeback`（抽取）、检索改写（可选）。其余均为确定性代码。
3. **Web 端是产品最终形态**：作者在网页里走完 Layer 1→5 全流程；MCP 面向 AI 客户端用户；CLI 只做 init/status/export 等本地管理。Web 内的聊天助手由 FastAPI 后端穿过 core 调 litellm，图谱通过 compose_context（进）与 extract_and_writeback（出）参与每次对话，不绕过 core。
4. **提案-diff-确认范式贯穿三端**：AI 产出永远是提案，落库必须作者确认（#4）。

### 7.2 技术选型（已定）

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.12+ | |
| 引擎核心 | 纯 Python 包 `snowel-core` | 领域逻辑零框架依赖 |
| MCP | 官方 `mcp` Python SDK，stdio 起步 | streamable HTTP 后续 |
| CLI | `typer` | 薄壳 |
| Web 后端 | `FastAPI` | 只做路由/鉴权/会话，不写领域逻辑 |
| Web 前端 | `React` + Vite + TypeScript | 主创作界面 |
| 图存储 | **SQLite 单库**：节点表 + 边表 + JSON 属性列，递归 CTE 遍历 | 单文件可 git 管理；万级节点性能足够 |
| 全文检索 | SQLite **FTS5**（中文分词 simple/jieba） | |
| 向量 | **sqlite-vec** | 兜底语义召回，同库管理 |
| LLM 接入 | **litellm** | 供应商可换；生成用大模型、回写抽取可用小模型（#26） |
| 校验/统计 | 纯 Python | POV 分布、节奏可视化等非 AI 校验（#21 #22） |

明确不采用：Neo4j/外部图库（单作者本地场景部署成本 > 收益）、独立向量数据库。

### 7.3 数据模型基线（对应 #0–#31 的收敛结论）

1. **本体 = 核心本体 + 可插拔属性组**（#0 #2 #16）：题材扩展包只提供属性组，不做整模板替换；节点支持多类型叠加（#18）。
2. **事件溯源**：append-only 事件日志 + 物化当前图；血缘/版本/回滚/冻结线 retcon/统一 revision 流程全部基于它（#5 #9 #29 #31）。
3. **关系是节点**：Relationship 带起止拍与强度曲线（#17）；MicroBeat 挂 Scene 下（#30）。
4. **多轨道 Timeline**（#20）：现实轨/异空间轨/回忆轨，Layer 4 前定稿。
5. **伏笔为独立横切实体**：多层定位 + 层间自动传播（#6 #13）；AI 自埋伏笔标 origin（#14）。
6. **正典分层**：图谱=结构化正典，正文=叙事正典；回写分级入典（#24 #25）。

### 7.4 落地顺序（建议）

1. `snowel-core`：本体 schema + 事件溯源存储层 + 基础图查询（先支撑 Layer 1/2）
2. MCP Server + CLI 薄壳，接入 AI 客户端验证流程
3. 回写环 + 混合检索（Layer 5 生死线）
4. FastAPI + React Web 创作界面（产品形态收口）

> 顺序理由：Web 界面是最终形态但不是第一验证工具；先在 MCP/CLI 里把流程与图谱跑通（成本低、迭代快），核心稳定后再包 Web 壳。
