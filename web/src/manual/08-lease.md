## 租约与多端

Snowel 是本地单机工具，但一本书可以同时从多个入口打开：Web、MCP、CLI 都能连同一个项目。为了保证不出现"两端同时写乱账本"，它用一张**写租约（lease）**来当总闸：同一时刻，全项目只有一个写者。

### 单写者与只读降级

谁先抢到写租约谁写，其余入口自动降级为**只读**：

| 入口 | 启动方式 | 抢不到租约时 |
|---|---|---|
| Web | `snowel web` | 页面顶部黄条横幅"只读模式：写租约由 XX 持有"，写按钮禁用 |
| MCP | `snowel mcp`（或客户端配置启动） | 写类工具调用被拒，读类照常 |
| CLI | `snowel status` 等命令 | 管理命令天生只读（不抢租约）；`seal` 等写命令抢不到即报错退出 |

只读不是残废态：浏览流程树、看可视化、查提案、检索、看对账状态都照常可用——只读降级读不限。页面上判断当前身份看顶栏右侧小圆点：绿色写会话、黄色只读。

### 心跳续租：不锁死、不双写

写租约不是死锁：持有者会按固定间隔心跳续租（默认过期窗 30 秒，心跳约为其三分之一）。进程正常退出会主动还租；进程崩溃则心跳停止，租约过期后其他入口即可抢写。持有期间若租约意外丢失（比如被强杀后又被他端抢走），会话立即翻转为只读并显示新的持有者——不存在两个写者并存的窗口。

日常用法：Web 是主写入口，挂着别关；想在 AI 客户端里临时驱动创作，先看 Web 是否在写（绿点），是则直接用 Web 的聊天侧栏，否则让 MCP 抢租约。

### MCP 走 HTTP：`snowel mcp --http`

MCP 默认走 stdio（AI 客户端拉起子进程即用，无需网络）。如果客户端在不同机器、或你只想用 HTTP 连接，加 `--http` 切换到 streamable HTTP 传输：

```bash
snowel mcp --http                          # 默认只监听本机 127.0.0.1:8642
snowel mcp --http --host 0.0.0.0 --token 我的口令   # 供局域网访问，必须带 token
```

三条安全规则务必记住：

- **默认只听本机**：`--http` 不带 `--host` 时只绑 `127.0.0.1`，外部机器连不上，想局域网用必须显式 `--host 0.0.0.0`（或 IPv6 的 `::`）。
- **通配地址强制 token**：绑 `0.0.0.0`/`::` 却不给 `--token`，直接拒绝启动——不给无鉴权全网卡监听留口子。
- **token 不对即 401**：客户端请求没带 token 或带错，服务端返回 401 拒绝。口令自定义即可，配进客户端的 Bearer token 设置里。

工具层面，HTTP 模式与 stdio 的工具清单完全一致，客户端无感切换。

### 项目定位：每个入口怎么找到书

每个进程绑定一个项目，定位优先级三端一致：显式 `--project`（或 `-p`）> 环境变量 `SNOWEL_PROJECT` > 当前目录。同时创作多本书，就起多个实例各绑各的项目——租约按项目独立，互不影响。

### 多端协作小抄

- 用 CLI 做**管理**：`init` / `status` / `backup`（一致性备份）/ `export`（导出 md/txt）/ `seal`（封卷）/ `ext`（扩展包管理，见《扩展包》）；CLI 不做交互式创作。
- 用 Web 做**创作**：三栏界面 + 聊天 + 可视化，是功能最全的形态。
- 用 MCP 做**代理**：在 AI 客户端里用自然语言驱动全流程，六工具见《聊天侧栏》与《提案与确认》。
