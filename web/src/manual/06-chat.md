## 聊天侧栏

右栏下方的聊天侧栏是随叫随到的创作搭子：你可以用自然语言让它查设定、推进流程、发起生成，它产出的东西照旧全部进提案队列等你确认。

### 发起对话

输入框里直接打字，Enter 发送（Shift+Enter 换行）。回复以打字机效果逐字渐显；如果 AI 决定调用工具，你会先看到一张工具卡片（转圈表示进行中），工具返回后卡片就地更新成败与摘要。生成类调用入队提案后，聊天底部会出现"已入队 N 个提案 → 去确认"的链接，点了直接跳到工作区提案列表。流进行中可点"中断"（Esc 同效）随时打断；出错时红条会给出原因并可重试。

注意：聊天挂的是写会话守卫——只读模式下聊天不可用（见《租约与多端》）。

### 它能帮你做什么

聊天 AI 手里有一份固定的小工具清单，全会话可见：

| 工具 | 用途 | 示例指令 |
|---|---|---|
| generate | 生成某层产物提案 | "把这句前提扩成梗概""给主角写角色档案" |
| expand_volume | 卷级展开：产卷主题 + 卷三幕提案 | "为第三卷做卷级展开" |
| expand_chapter | 章级展开：按序产章意图、微节拍组、正文三条提案 | "展开第一章" |
| query | 只读查询：全文/语义检索（search）、按名查找节点（find）、按拍号回放世界状态（state_at）、查节点详情（node） | "现在谁的刀法最高""第 40 拍时还有哪些伏笔没收" |
| register_foreshadow | 注册伏笔提案 | "登记伏笔'生锈的怀表'，种在第一章" |

清单里刻意**没有**确认、否决、封卷——AI 只能提议，裁决永远在结构化面板（见《提案与确认》）。所以跟它聊得再嗨，图谱也不会在你不点头时变样。

### 聊天检索走统一管线

聊天里所有查询（上表 query 工具，尤其 search）走的都是与正文检索、写前上下文组装**同一条混合检索管线**（hybrid retrieval：图谱精确拉取为主，全文 FTS5 与向量召回兜底）。这意味着两件事：

- 聊天里问"还记得谁提过怀表吗"，它看到的检索结果与你在生成时注入上下文的内容同源，不会出现"聊天知道、写作时忘了"的两套记忆；
- 每次检索上下文都会记入检索审计（retrieval_audit），你事后可以核对"它当时到底看了什么"——校准方法见《检索与偏好》。

### 当搭子而不当枪手

小技巧：让聊天先查后写。"先查一下女主现在的伤势，再写她强行赶路的正文"——AI 会先调检索确认设定，再发起正文提案，产出与既有事实打架的概率小得多。如果产出仍与设定冲突，级联检查会在你确认时把矛盾摆到台面上。
