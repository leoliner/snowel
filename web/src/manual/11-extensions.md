## 扩展包

核心本体自带通用属性组（动机、谎言信念、弧光……），但写无限流需要"排名轨迹"，写玄幻需要"境界根骨"——这些题材专属的数据结构，用扩展包（extension pack）注入。一个扩展包就是一个目录，装两类东西：**属性组**（attribute group，节点的附加字段）和**级联规则**（cascade rule，随一致性检查运行的题材守则）。生成偏好、文风、角色模板刻意不在载荷之内——包只管结构，不管文风。

### 放哪里：双位置发现

| 位置 | 生效范围 | 适用场景 |
|---|---|---|
| `<项目>/extensions/包目录/` | 仅本项目 | 试验改包、项目专属结构 |
| `~/.snowel/extensions/包目录/` | 本机全部项目 | 常用题材结构一次安装 |

先扫全局、再扫项目，同名（以包内 schema.json 的 `name` 字段为准）时项目侧覆盖全局侧——想魔改一个包，复制到项目侧随便改，不影响全局原件。放好即被发现，无需注册；仓库自带的预制包 `extensions/infinite-flow/`（无限流：空间资历、排名轨迹、能力清单、盲区特权四组 + 一条示范规则）就是可运行范例，抄它的结构入门最快。

### 四条命令：`snowel ext`

扩展包只经 CLI 管理（Web 与 MCP 刻意不设此面——挂载等于把包里的 Python 代码接入引擎，这种事必须想清楚再做）：

```bash
snowel ext list                   # 发现全集 × 挂载态（来源标注：项目/全局/孤儿）
snowel ext mount infinite-flow    # 挂载：属性组即刻可写，规则同引擎生效
snowel ext unmount infinite-flow  # 卸载：有活跃引用时拒绝并列出节点
snowel ext status                 # 逐包健康明细 + 警告回顾
```

- **挂载**后：属性组挂到节点上可用，hooks 里的级联规则随每次一致性检查运行；挂载前已写入的旧数据不受影响（保持未受管状态，零回溯），随时可装。
- **卸载**有闸门：任一属性组还被活跃节点引用就拒绝，并列出这些节点 id——先用 retcon/迁移清掉引用再卸。卸载后数据保留，字段降级为未受管照存，重新挂载即恢复。
- **目录被手删/包损坏**不会崩：启动给警告、`ext list` 标"孤儿"、数据照存，目录恢复即自动重激活。

### 升级不自动跟随

一条容易踩的规矩：**改了包的内容，已挂载的项目不会自动跟上**。挂载时引擎记住了包内容的指纹（digest，内容哈希）；之后磁盘上的 schema.json 一旦变更，已挂载会话维持旧形状，`ext list` 与 `ext status` 会标注"schema 与挂载时不一致"。想让新结构生效，**再执行一次 `snowel ext mount 包名`（重新挂载）**。看到"改了怎么没生效"，先想到这一条。

### 只装可信来源

安全红线说三遍都不多：挂载即把 hooks.py 作为 Python 代码接入引擎进程。**只装可信来源的包**；替别人或让 AI 替你装第三方包前，先人工读过它的 hooks.py。自己写包的完整规范——schema 字段类型、hooks 规则契约、测试与发布流程——见仓库 `extensions/SKILL.md`（制作规范，全部示例取自预制包）。

### 与正典的关系

扩展包是纯增量：`snowel init` 不预置任何题材包，装与不装不影响既有数据；同一项目不同时期可挂不同包。挂载事件进入事件日志，全库重建（rebuild）时可重放——包的历史也是正典的一部分。
